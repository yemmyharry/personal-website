THE PROBLEM

What needed
to work.

An appointment can only be booked once, even when people retry requests or attempt to reserve the same slot. The interface also needs a clear way to find and cancel an existing booking.

MY CONTRIBUTION

Where I
got involved.

Built the appointment API and web page for a Koya engineering assessment. The repository includes API tests, PostgreSQL integration tests, and a browser booking-flow suite.

Booking experience

Browse slots by doctor, book, find a booking by reference or email, and cancel.

Retry & conflict handling

Use idempotency keys for retries and reject conflicting or duplicate bookings.

Verification

Include tests for API behavior, PostgreSQL integration, and the complete browser journey.

A DECISION WORTH TALKING ABOUT

The details
carry the product.

Treat an idempotent retry differently from a new request. Reusing a key with a different body returns 422; repeated fresh attempts are rate limited.

EXPLORE THE EVIDENCE

Source & documentation

Assessment project, not a deployed clinical service. Features and tests are documented in the public repository; no patient adoption or production metrics are claimed.
